## Product-1 restart validation refactor

Simplified `fuv_detector_file_status()` after review showed that both the
original implementation and the first attempted refactor carried too much
validation machinery for a scientific orbit-processing script.

The final implementation follows `binned_file_status()` directly. It checks
product identity, preprocessing label, time tolerance, source paths, selected
image fields, and required array shapes in one readable function. It retains
the four existing status values and atomic partial-file publication. It does
not add helper validators, configuration JSON, processing fingerprints,
detailed status objects, or restart-time source hashing. Source SHA-256 and
software identity remain in the product for provenance, and documentation-only
attribute changes do not affect restart status.

Verification: 12 focused detector/coregistration/footprint tests pass. The
full repository suite reports 83 passed and the same four pre-existing
36-by-36 versus 46-by-46 grid/Zhang--Paxton lookup failures.

## Experimental detector Product 2

Implemented the documented image-ratio `precipitation_detector` slice in
`icbuilder/precipitationdetector.py` with serial orbit orchestration in
`scripts/pipeline/make_precipitation_detector_orbit_files.py`.

The calculation uses the Product-1 time and WIC detector geometry unchanged.
It matches definitive GFZ Kp, evaluates Hardy or constant proton energy on
each frame's detector MLAT/MLT, infers Fp from coregistered SI12 counts,
proton-corrects WIC/SI13, and applies the shared icPhysics image-ratio method.
All WIC frames survive; method validity is stored per pixel and requires all
three channels. The NetCDF product is self-contained for geometry, time,
support, and precipitation state and directly references its Product-1 file.

The analytic uncertainty path is retained only as a labelled parity result.
Product 1 provides no detector-count uncertainty and mapped-SI covariance is
omitted. The experimental calculation maps SI12 counts before flux inference;
the alternative order remains an explicit numerical test before scientific
adoption.

Six focused new tests pass; the focused detector/existing-precipitation subset
has 33 passes. The full suite has 89 passes and the same four known grid/lookup
failures. An isolated run on the 20-frame orbit-0085 excerpt produced an
18.94-MB Product 1 in 143.11 s and a 24.51-MB Product 2 in 17.68 s with 688 MB
peak RSS. Product 2 retained 380,040 method-valid cell-frames (29.0%).

Portfolio impact: Central update needed: Yes. The detector-first migration now
has experimental Product-1 and image-ratio Product-2 file boundaries. Product
3 and detector-compatible Zhang--Paxton remain unimplemented.

## Product-1 parallel run and projected-geometry fix

Added orbit-level multiprocessing to the detector Product-1 script through
`--workers`; one is serial and larger values use `process_map`. A Halley run
then completed 1,670 of 1,687 scheduled items before SciPy rejected a WIC
Delaunay input containing NaN. The source coordinates were finite, but one or
more pixels lay behind the frame's local tangent plane and projected to NaN.

The transform now triangulates only pixels that remain finite after local
projection. A regression test includes a finite, geographically isolated WIC
pixel behind the tangent plane. Worker errors now include the orbit number,
and the status line uses the requested output folder. Sixteen focused
Product-1/coregistration/footprint tests pass. Completed atomic outputs can be
retained and the interrupted corpus resumed without `--overwrite`.

Portfolio impact: Central update needed: No. This fixes execution robustness
